# 사주300 사업·해석 프롬프트 설계서

작성일: 2026-11-12

> 이 문서는 Kiro가 '사주300' 웹서비스를 만들 때 기준으로 삼는 설계서다.
> 판정·확신도·시기는 코드가 정하고, AI는 문장만 쓴다.

---

## 1. 한 줄 요약

사주300은 **"질문 하나에 300원, 결론부터 말하고 근거까지 보여주는 사주"**다. 긴 리포트 대신 지금 궁금한 질문 하나에만 답한다.

- **고객**: 몇천 원짜리 긴 리포트보다, 지금 궁금한 것 하나를 빨리 알고 싶은 20~30대 모바일 사용자
- **해석 차별화**: 판정·근거 칩·확신도·반대 신호를 함께 보여주는 "판결형 해석". 모든 답이 한 사람의 사주 프로필에 맞춰져 있어 질문끼리 서로 모순되지 않는다
- **돈 버는 구조**: 무료 사주 프로필 카드로 사람을 모으고 → 내 사주에 맞는 질문을 추천해 장바구니로 여러 개 결제 → 카테고리 묶음 → 답에 나온 시기가 오면 알림을 보내 다시 방문
- **결제**: 장바구니 단위의 건별 즉시결제. 충전식은 쓰지 않는다 (사주·운세 업종 심사에 유리)
- **초기 목표(가설)**: 첫 결제 평균 5문항(1,500원), 결제액 대비 공헌이익 70% 이상

## 2. 시장에서 배운 것

시장 가격은 990원부터 10만 원대까지 넓고, 서비스 간 차이는 AI 모델이 아니라 해석 설계에서 나온다. 300원은 확인된 서비스 중 가장 낮은 가격이라, 가격보다 **"질문 단위로 판다"**는 점이 차별점이 된다.

| 서비스 | 형태·판매 방식 | 잘하는 것 | 사주300에 적용 |
| --- | --- | --- | --- |
| 운세위키 | 웹, 3,900원 주력 단건 + 구독 | 고민 기준 메뉴, 무료 신살 조회로 검색 유입, 흐림 미리보기 | 무료 신살 페이지는 가져오되, 결과는 이메일(최대 2시간) 대신 화면에서 즉시 |
| 사주플러스 | 웹, 리포트 단위 구매 | 카드·간편결제 4종·가상계좌, 60일 다시보기 | 결제 수단과 다시보기 정책 참고. 우리는 보관함 무기한 |
| 사주아이 | 온라인, 990원 리포트 | 가성비 입소문, 운세 그래프, 결과 링크 공유 | 가장 가까운 경쟁자. 결과 공유 링크를 가져오고 "질문 하나만 콕"으로 차별화 |
| 포스텔러 | 앱 위주, 재화 충전 | 무료 만세력으로 모객, 가입자 750만 명 | 무료 도구 → 유료 구조는 가져오되, 재화 충전은 쓰지 않음 |
| 점신 | 앱, 무료 운세 → 1:1 상담 | 2030 비중 65.6%, 무료 결과에서 "주의할 점"으로 유료 연결 | 사람 상담 대신 "내 사주에 맞는 질문 추천"으로 연결. 불안을 파는 방식은 피함 |
| 사주캣 | 웹, 무료 채팅형 | 고양이 캐릭터와 대화하는 UX | 초기 절기 계산 오류 사례 → 만세력 검증을 최우선으로 |
| 천명 | 사람 상담 + AI 상담노트 | 상담 내용을 AI가 요약 | 사람 상담은 하지 않음. "나의 답 모아보기" 요약 기능에 응용 |

세 가지 공통점이 보인다. 무료 도구로 사람을 모으고, 작은 첫 결제로 구매 장벽을 낮추며, 결과를 공유하게 만든다.

## 3. 해석 차별화: 증거로 말하는 사주

사주300의 해석은 **판정 → 근거 → 확신도 → 반대 신호 → 처방** 순서로 짧게 답한다. 흔한 AI 사주가 길고 두루뭉술하며, 근거가 안 보이고, 물을 때마다 달라지는 문제를 정면으로 푸는 설계다.

1. **판정 먼저**: 첫 문장이 결론이다. 판정 형식은 질문마다 고정한다 (예/아니오/조건부, 시기, 유형, 등급 등).
2. **근거 칩**: 모든 주장 옆에 [세운 정관] 같은 칩을 붙이고, 누르면 쉬운 설명이 나온다. 칩은 계산값에서만 나온다.
3. **확신도 강·중·약**: 같은 방향 신호와 반대 신호의 수로 코드가 정한다. "약"이면 "사주만으로 단정하기 어려워요"라고 솔직하게 말한다.
4. **반대 신호 한 줄**: "다만 ○○은 반대로 작용해요." 듣기 좋은 말만 하지 않는다는 신뢰를 만든다.
5. **처방 1개 + 기한**: "4월 안에 새 모임 하나에 등록하세요." 바로 할 수 있는 행동 하나만 준다.
6. **하나의 사주, 하나의 이야기**: 처음에 "사주 프로필"(핵심 키워드 3개, 인생 테마)을 만들어 고정한다. 이후 모든 답변이 이 프로필을 참조하므로, 600개 질문의 답이 서로 모순되지 않는다.

**말투**: 솔직한 선배 명리사. "~해요"체, 짧은 문장, 공포 금지. 운명을 단정하지 않고 "흐름"과 "선택"으로 말한다. 캐릭터 채팅형(사주캣)과 긴 리포트형(운세위키) 사이의 빈자리다.

**답변 예시**: 질문 "다음 연애는 언제 시작될까?"

| 칸 | 내용 |
| --- | --- |
| 판정 | 2027년 5월과 9월이 가장 유력해요. (확신도: 중) |
| 근거 칩 | [세운 정관] 배우자 기운이 들어오는 해 · [5월 월운 묘목] 태어난 날의 자리와 합 · [도화] 매력이 드러나는 때 |
| 해석 | 원래 신중하게 사람을 고르는 분이라, 두 번째 만남부터 마음이 열려요. (프로필 키워드와 연결, 350~500자) |
| 반대 신호 | 다만 상반기에는 경쟁 기운이 강해, 인연이 경쟁 구도로 시작될 수 있어요. |
| 처방 | 4월 안에 새 모임 하나에 등록하세요. |
| 피할 것 | 아는 사람의 연인 주변 관계 |

예시의 사주 요소는 형식을 보여주기 위한 가상값이다.

## 4. 상품·가격 설계

질문 1개 300원은 그대로 두고, 그 위아래로 무료 상품과 묶음 상품을 붙여 객단가를 올린다.

| 단계 | 상품 | 가격 | 역할 |
| --- | --- | --- | --- |
| 무료 | 내 사주 프로필 카드: 명식표, 핵심 키워드 3개, 인생 테마, 공유 이미지 | 0원 | 모객·공유·가입 유도 |
| 무료 | 신살 조회 (도화·역마·화개·귀인·삼재 등) | 0원 | 검색 유입 |
| 핵심 | 질문 1개 | 300원 | 첫 결제 장벽 최소화 |
| 핵심 | 2인 궁합 질문 1개 | 500원 | 상대 초대로 신규 유입 |
| 묶음 | 카테고리 30문항 전체 | 개별가 합계 9,000원 → 묶음가 예: 5,900원 | 객단가 상승 |
| 시즌 | 2027 신년운세 + 12개월 점수 그래프 | 300원 | 연말연초 트래픽 흡수 |
| 재방문 | 시기 알림: 답에 나온 달이 오면 알림 + 그 달 질문 추천 | 0원 (가입 필요) | 재구매 |
| 2단계 | 월 구독 "이달의 질문 5개" | 예: 월 1,900원 | 결제사가 정기결제를 승인한 뒤 |

**장바구니 결제 원칙**

- 질문을 여러 개 담아 한 번에 결제하고, 결제 즉시 모든 답을 보여준다 (건별 즉시결제).
- 장바구니에 "같은 사주로 함께 보면 좋은 질문" 3개를 추천한다.
- 1개 300원 결제도 허용한다. 단, 결제사에 건당 최소 수수료가 있으면 최소 결제를 900원(3문항)으로 바꾼다.
- 묶음가의 "정가"는 실제 개별가 합계만 쓴다. 근거 없는 할인 표시는 하지 않는다.

**왜 300원을 지키나**: 990원(사주아이)도 "가성비"로 통한다. 300원은 망설임 없이 누르는 가격이고, 이름 자체가 가격을 설명하는 광고다.

## 5. 성장 구조

300원 모델은 박리다매라 트래픽이 전부다. 광고비 대신 **검색·공유·초대**로 사람을 모으는 구조를 처음부터 설계한다.

**구매 흐름**

1. 검색·SNS로 유입
2. 무료 사주 프로필 카드 보기 (가입 없이 보기, 저장은 가입)
3. "내 사주가 가장 궁금해할 질문 3개" 추천 (예: 도화가 강하면 연애 질문을 위로)
4. 장바구니에 담고 결제
5. 결과 화면 하단에서 이어지는 질문 추천
6. 답에 나온 달이 오면 알림 → 다시 방문

**사람을 모으는 장치 4가지**

- **질문 600개 = 검색 페이지 600개**: 질문마다 "사주로 이 질문을 보는 법" 소개 페이지를 만든다. "다음 연애 언제 사주" 같은 검색어에 걸린다.
- **무료 신살 페이지**: 운세위키처럼 신살별 조회 + 해설 글. 아래에 관련 300원 질문을 연결한다.
- **궁합 초대 링크**: 상대가 링크로 들어와 자기 정보를 넣으면 상대도 무료 프로필 카드를 받는다. 한 명이 한 명을 데려오는 구조다.
- **공유 카드**: 프로필 카드와 결과의 판정·근거 칩만 인스타 스토리 크기 이미지로 만든다. 본문은 공개하지 않는다.

**시즌 달력**: 11~2월 신년운세, 2월 밸런타인 궁합, 3월·9월 이직 시즌, 11월 수능·입시. 시즌마다 대표 질문 하나를 메인 배너에 올린다.

## 6. 수익 구조

질문 5개(1,500원)를 한 번에 결제하면 약 1,158원(77%)이 남는다. 건당 최소 수수료와 AI 비용, 이 두 가지가 수익성을 좌우한다.

| 항목 | 질문 5개 결제 | 질문 1개 결제 | 가정 |
| --- | --- | --- | --- |
| 결제 금액 | 1,500원 | 300원 | 가격에 부가세 포함 |
| 부가세 | −136원 | −27원 | 결제 금액의 1/11 |
| 결제 수수료 | −56원 | −11원 | 카드 3.4% + 부가세 (토스페이먼츠 예시), 최소 수수료 없다고 가정 |
| AI 비용 | −150원 | −30원 | 질문당 30원 목표. 모델과 길이에 따라 달라 실측 필요 |
| **남는 돈 (공헌이익)** | **약 1,158원 (77%)** | **약 232원 (77%)** | |

건당 최소 수수료가 예를 들어 100원이면, 질문 1개 결제에서 남는 돈은 약 133원(44%)으로 떨어진다. 장바구니 결제가 필수인 이유다.

**규모 시나리오** (결제 1회 평균 2,000원, 공헌이익 77% 가정)

| 월 결제 건수 | 월 매출 | 월 공헌이익 |
| --- | --- | --- |
| 1,000건 | 200만 원 | 약 154만 원 |
| 5,000건 | 1,000만 원 | 약 770만 원 |
| 20,000건 | 4,000만 원 | 약 3,080만 원 |

**광고비 원칙**: 클릭당 수백 원짜리 유료 광고는 첫 결제 1,158원을 쉽게 넘어선다. 유료 광고는 재구매율이 확인된 뒤에만 쓴다. 초기에는 검색 페이지와 공유·초대가 주 유입 채널이다.

**고정비**: 결제사 연관리비(예: 토스페이먼츠 연 11만 원), 도메인, 호스팅·DB. 호스팅·DB는 무료 요금제로 시작하고 사용량에 따라 올린다.

## 7. 해석 엔진 설계

판정·확신도·시기는 코드가 정하고, AI는 문장만 쓴다. 그래서 같은 사주에 같은 질문을 하면 항상 같은 결론이 나온다. 이 구조가 다른 서비스가 쉽게 따라 하지 못하는 핵심 자산이다.

**처리 흐름** (코드 = 규칙 기반, AI = LLM 호출)

1. **만세력 계산** (코드): 절기·서머타임 반영해 사주 8글자와 대운·세운·월운 계산
2. **사주 프로필** (AI, P1): 명식당 한 번만 쓰고 저장해서 고정
3. **신호 계산** (코드): 질문 레시피에 적힌 신호를 계산
4. **판정·확신도·시기** (코드): 같은 입력이면 항상 같은 결과
5. **캐시 확인** (코드): 같은 (명식 + 질문 ID + 기준 연월)의 답이 저장돼 있으면 AI를 부르지 않고 바로 8번으로
6. **문장 작성** (AI, P2): 판정은 바꾸지 못하고 설명만 쓴다
7. **검수** (코드 + AI 표본, P5): 근거·금지어 확인. 실패하면 6번으로 돌아가 한 번 다시 생성
8. **화면 표시·저장**: 결과를 보여주고 보관함에 저장

AI는 프로필과 문장 두 곳에서만 일한다. 같은 답이 저장돼 있으면 AI를 부르지 않아 비용이 줄고 결론도 항상 같다.

**질문 레시피**: 질문마다 "어떤 신호를 보고, 얼마나 믿고, 어떻게 판정하는지"를 데이터로 적는다. 예시는 "다음 연애는 언제 시작될까?"다.

```json
{
  "id": "L04",
  "title": "다음 연애는 언제 시작될까?",
  "verdictType": "시기(월)",
  "timingScope": "다음 12개월",
  "signals": [
    { "key": "spouseStarInYear",       "label": "세운에 배우자성",   "weight": 3, "dir": "+" },
    { "key": "monthHarmonyDayBranch",  "label": "월운이 일지와 합",   "weight": 2, "dir": "+" },
    { "key": "dohwaActiveInMonth",     "label": "그 달의 도화",       "weight": 1, "dir": "+" },
    { "key": "monthClashDayBranch",    "label": "월운이 일지를 충",   "weight": 2, "dir": "-" },
    { "key": "rivalStarStrongInYear",  "label": "세운에 비겁 강함",   "weight": 1, "dir": "-" }
  ],
  "verdictRule": "월별 점수 상위 2개월. 1위와 3위 점수 차가 작으면 확신도를 한 단계 낮춤",
  "safety": []
}
```

**확신도 규칙 (초안)**: 지지 신호 점수 합 − 반대 신호 점수 합으로 정한다. 5점 이상은 강, 2~4점은 중, 1점 이하는 약. 출생 시간이 없으면 한 단계 낮춘다.

**공통 신호 라이브러리**: 신호는 질문마다 새로 만들지 않고, 40~60개의 공통 신호(배우자성 상태, 재성 세기, 일지 합충, 역마 활성, 용신 세운 등)를 만들어 조합한다.

**현실적인 순서**: 600문항 모두에 정교한 레시피를 처음부터 만들지 않는다. 카테고리별 인기 질문 10개, 총 60개는 정교한 레시피로 시작하고, 나머지는 카테고리 공통 레시피를 쓴다. 신호의 가중치는 명리 전문가 검수를 받는다.

## 8. AI 프롬프트 세트

프롬프트는 6개다. P1과 P2가 서비스의 핵심이고, P3·P4는 P2에 덧붙이는 규칙, P5·P6은 운영용이다. 모두 서버에서만 호출하고 temperature는 0~0.3으로 둔다.

| 번호 | 이름 | 언제 | 호출 횟수 |
| --- | --- | --- | --- |
| P1 | 사주 프로필 | 사주 정보를 처음 입력했을 때 | 명식당 1회, 저장 후 재사용 |
| P2 | 질문 답변 | 질문을 결제했을 때 | 명식 + 질문 + 기준 연월당 1회, 캐시 |
| P3 | 궁합 추가 규칙 | 2인 질문 | P2에 덧붙임 |
| P4 | 신년·월별 추가 규칙 | 신년운세 | P2에 덧붙임 |
| P5 | 답변 검수 | 답변 생성 직후 | 코드 검사는 매번, AI 검사는 표본 5% |
| P6 | 질문 소개 페이지 | 질문 등록 시 | 질문당 1회, 사람이 검토 |

### P1. 사주 프로필

```text
너는 '사주300'의 해석 작가다. 아래 [계산 결과]는 명리 공식으로 이미 확정된 값이다.
너는 계산하지 않는다. 이 값으로 이 사람의 '사주 프로필'을 쓴다.
이 프로필은 저장되어, 이 사람의 모든 질문 답변의 기준이 된다.

[출력: JSON만]
{
  "keywords": [
    {"word": "두 단어 이내 키워드", "line": "한 문장 설명", "basis": ["계산 결과의 요소명"]}
  ],                                  // 정확히 3개
  "theme": "인생 테마 한 문장, 30자 이내",
  "strength": "가장 큰 강점 한 문장",
  "watch": "조심할 경향 한 문장 (비난이 아니라 사용설명서처럼)",
  "shareLine": "공유 카드에 들어갈 한 줄, 20자 이내"
}

[규칙]
1. basis에는 [계산 결과]에 실제 있는 요소만 쓴다.
2. 누구에게나 맞는 말("때로는 외롭지만 사람을 좋아해요")은 금지다. 이 사주에만 해당하는 말을 쓴다.
3. 세 키워드는 서로 다른 면(기질, 관계, 일·돈)을 다룬다.
4. "~해요"체. 공포·비하 표현 금지.

[계산 결과] {chart_json}
```

### P2. 질문 답변 (핵심)

```text
너는 '사주300'의 해석 작가다. 질문 하나에 답한다.
판정(verdict), 확신도(confidence), 시기(timing)는 코드가 이미 정했다.
너는 그것을 바꾸지 않고, 왜 그런지 사람이 납득하도록 설명한다.

[입력]
- question: 질문 정보 (id, title, verdictType)
- verdict: 코드가 정한 판정
- confidence: 강 | 중 | 약
- signals_for: 판정을 지지하는 신호 (label, plain)
- signals_against: 반대 신호 (label, plain)
- profile: 이 사람의 사주 프로필 (P1 결과)
- user: 호칭, 출생시간 유무, 기준 날짜

[출력: JSON만]
{
  "headline": "판정을 담은 첫 문장, 40자 이내",
  "evidence": [{"chip": "signals_for의 label", "why": "쉬운 설명 1문장"}],   // 2~3개
  "story": "해석 2~3문단, 총 350~500자",
  "counter": "반대 신호 한 문장. signals_against가 없으면 빈 문자열",
  "action": {"do": "행동 1개", "by": "기한"},
  "avoid": "피할 것 1개",
  "confidenceNote": "확신도가 약이거나 출생시간이 없을 때만 한 문장"
}

[규칙]
1. headline은 verdict를 그대로 말한다. 돌려 말하거나 바꾸지 않는다.
2. evidence의 chip은 signals_for의 label만 쓴다. 새 근거를 만들지 않는다.
3. story 첫 문단은 profile.keywords 중 하나와 연결한다 ("원래 ○○한 분이라...").
4. profile과 모순되는 성향 묘사를 하지 않는다.
5. 누구에게나 맞는 말(바넘 문장)을 쓰지 않는다.
6. 공포·저주·불행 단정 금지. 나쁜 신호는 '주의할 흐름'과 '대처법'으로 쓴다.
7. 건강·임신·투자·법률은 단정하지 않고, 전문가 상담을 권하는 문장을 action 또는 story에 넣는다.
8. 명리 용어는 처음 나올 때 괄호로 쉽게 푼다. 예: 정관(나를 다듬는 규칙과 직장의 기운)
9. 말투는 솔직한 선배. "~해요"체, 짧은 문장, 감탄사·이모지 금지.
10. action은 기한 안에 실제로 할 수 있는 구체적 행동 하나다.

[질문] {question_json}
[판정] {verdict_json}  [확신도] {confidence}
[지지 신호] {signals_for_json}
[반대 신호] {signals_against_json}
[프로필] {profile_json}
[사용자] {user_json}
```

### P3. 궁합 추가 규칙 (P2 뒤에 붙임)

```text
[궁합 규칙]
- 두 사람을 "나"와 "그 사람"(이름이 있으면 이름)으로 부른다.
- 점수·등급은 입력값을 그대로 쓴다. 너는 점수를 정하지 않는다.
- 한쪽만 나쁘게 말하지 않는다. 부딪히는 점은 '서로 다른 점'과 '맞추는 방법'으로 쓴다.
- action은 두 사람이 함께 할 수 있는 행동으로 쓴다.
- 상대 출생시간이 없으면 confidenceNote에 그 사실을 쓴다.
```

### P4. 신년·월별 추가 규칙 (P2 뒤에 붙임)

```text
[신년운세 규칙]
- 출력에 months 배열을 추가한다: [{"month":"2027-01","line":"한 줄 조언, 25자 이내"}] 12개.
- 월별 점수와 '움직일 달/쉬어갈 달' 표시는 입력값이다. 너는 line만 쓴다.
- 월은 절기 기준이다. "1월"은 소한(1월 초)부터 입춘 전까지다.
- story는 600~900자로 늘린다.
```

### P5. 답변 검수

코드 검사(매번): JSON 형식, evidence의 chip이 signals_for 안에 있는지, headline에 판정 값(월·등급)이 들어 있는지, 글자 수, 금지어(죽음, 저주, 반드시 이혼, 필연적 불행 등). 하나라도 어기면 한 번 다시 생성하고, 두 번 어기면 운영자에게 알린다.

```text
[AI 검수, 표본 5%만]
아래 [답변]을 [입력값]과 비교하라. JSON만 출력한다.
{"invented": [입력값에 없는 사주 요소·시기 언급],
 "barnum": [누구에게나 맞는 문장],
 "fear": [공포·단정 표현],
 "profileConflict": [프로필과 모순되는 문장],
 "pass": true 또는 false}
```

### P6. 질문 소개 페이지 (검색 유입용)

```text
'사주300'의 질문 소개 페이지를 쓴다. 개인 사주 풀이가 아니라
"사주에서는 이 질문을 어떻게 보는가"를 설명하는 글이다.

[출력: JSON만]
{"h1": "질문 그대로", "intro": "2문장",
 "howWeRead": "이 질문에서 보는 사주 요소 3가지와 각각의 의미, 400~600자",
 "faq": [{"q": "", "a": ""}],   // 3개
 "metaDescription": "80자 이내"}

[규칙] 어떤 사람의 결과도 단정하지 않는다. 실제 이용자 수·후기·적중률을 언급하지 않는다.
마지막 문장은 "내 사주로 확인하기 (300원)"으로 끝낸다.
[질문] {question_json}  [레시피] {recipe_json}
```

## 9. 지표와 운영

매주 지표 8개를 보고, 매달 만족도 하위 10% 질문의 레시피를 고치거나 교체한다. 목표치는 출시 후 실측으로 다시 잡는 초기 가설이다.

| 지표 | 무엇을 재나 | 초기 목표(가설) |
| --- | --- | --- |
| 프로필 카드 생성률 | 방문자 중 사주 정보를 넣은 비율 | 30% |
| 첫 결제 전환율 | 프로필 생성자 중 결제한 비율 | 10% |
| 평균 장바구니 문항 수 | 결제 1회당 질문 수 | 5개 |
| 질문별 만족도 | 결과 하단 도움됨/아님 비율 | 80% |
| 30일 재구매율 | 첫 결제 후 30일 안에 다시 결제한 비율 | 20% |
| 궁합 초대 수락률 | 보낸 초대 링크 중 상대가 정보를 넣은 비율 | 40% |
| 질문당 AI 비용 | 생성 1회 평균 비용 | 30원 이하 |
| 환불·문의율 | 결제 건수 대비 환불 요청·문의 | 2% 이하 |

**운영 루틴**

- 매주: 지표 확인, "도움 안 됨" 답변 20개 직접 읽기
- 매달: 만족도 하위 10% 질문 레시피 수정, 안 팔리는 질문 교체, 시즌 배너 교체
- 분기: 명리 전문가와 신호 가중치 점검
- 실제 판매 데이터가 쌓이면 그때부터 "많이 본 질문 BEST 10"을 표시한다.

## 10. 리스크와 규정

가장 급한 것은 현재 사이트의 **"100만+ 누적 풀이", "4.8 평균 평점", "지금 가장 많이 보는 풀이 BEST 10" 문구**다. 출시 전이라 실제 데이터가 아니면 결제사 심사 전에 지운다.

| 리스크 | 왜 문제인가 | 대응 |
| --- | --- | --- |
| 근거 없는 실적·후기 표시 | 표시광고법상 허위·과장 광고 소지, 결제사 심사 반려 사유 | 실제 데이터가 쌓일 때까지 "추천 질문", "600문항", "300원"처럼 사실만 표시 |
| 결제사 심사 탈락 | 사주·운세는 유의업종. 이니시스·네이버페이는 받지 않음 | 자동생성 디지털 콘텐츠 + 건별 결제로 신청. 포트원·KG파이낸셜·KPN에 동시 문의 |
| 디지털 콘텐츠 환불 | 제공 시작 후 철회 제한은 사전 고지가 있어야 인정됨 | 결제 전 고지 + 동의 체크. 오류로 결과가 안 나오면 전액 환불. 약관은 법률 검토 권장 |
| 미성년자 결제 | 법정대리인 동의 없는 미성년자 계약은 취소될 수 있음 | 결제 시 성인 여부 확인, 만 14세 미만 가입 금지 |
| 만세력 오류 | 사주캣은 초기에 절기 대신 양력 달 기준으로 계산해 "사주가 틀린다"는 후기를 받음 | 한국천문연구원 데이터 기준 검증, 경계 케이스 테스트 |
| AI 비용 급증 | 트래픽이 늘면 질문당 비용이 수익을 잠식 | 캐시, 출력 길이 제한, 모델 선택, 질문당 비용 매주 확인 |
| 불안 마케팅 | 단기 전환은 오르지만 신뢰와 재구매를 해침 | "불안" 대신 "결정 도움"으로 포지셔닝. 공포 문구는 P5가 걸러냄 |
| 경쟁사 모방 | 문구·디자인 복제는 분쟁 소지 | 구조만 참고하고 문구·이미지는 직접 제작 |

법률 판단이 필요한 항목(약관, 환불, 미성년자)은 출시 전 전문가 검토를 받는다.

## 11. 8주 실행 순서

만세력과 신호를 먼저 검증하고, 결제는 결제사 승인이 나는 5~6주차에 붙인다. 사업자 서류와 결제사 신청은 개발과 동시에 진행해야 일정이 맞는다.

| 단계 | 기간 | 할 일 | 관문 (통과해야 다음 단계로) |
| --- | --- | --- | --- |
| 1. 기초 계산 | 1~2주 | 만세력 계산 모듈, 공통 신호 40~60개, 인기 60문항 레시피 | 경계 테스트 통과 |
| 2. 무료 카드·답변 | 3~4주 | 사주 프로필 카드, 답변 엔진(P2)·검수(P5)·캐시, 내부 테스트 50명 | 만족도 80% |
| 3. 결제·성장 | 5~6주 | 장바구니 결제(포트원), 궁합 초대 링크, 시기 알림(이메일) | 결제사 승인 |
| 4. 정식 오픈 | 7~8주 | 질문 소개 600페이지, 무료 신살 페이지, 사실 기반 문구 점검 | 오픈 |

함께 진행: 사업자등록·통신판매업 신고·약관(1~4주) → 결제사 신청·심사(4~6주)

관문을 통과하지 못하면 다음 단계로 넘어가지 않는다. 특히 만세력 경계 테스트가 틀리면 이후 모든 답이 틀리므로 1단계에 가장 시간을 쓴다.
