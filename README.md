# 사주300 — Kiro 전달용 폴더

| 파일 | 내용 |
|---|---|
| `docs/business-plan.md` | 사업·해석 프롬프트 설계서 전체 (Kiro의 기준 문서) |
| `.kiro/steering/*.md` | Kiro가 작업할 때마다 자동으로 읽는 규칙 4개 |
| `data/questions.json` | 질문 데이터 초안 (240문항, 8개 카테고리) |

> `.kiro`처럼 점(.)으로 시작하는 폴더는 숨김 폴더로 보일 수 있어요. 지우지 마세요.
> 사이트에 600문항을 쓰고 있다면, 그 질문 목록으로 `data/questions.json`을 바꿔 넣으세요.

## 사용 방법

1. 압축을 풀고 Kiro에서 **Open Folder**로 이 폴더(`saju300-kiro`)를 엽니다.
2. 왼쪽 Kiro 메뉴의 **Steering**에 `product`, `tech`, `structure`, `saju-rules` 4개가 보이는지 확인합니다.
3. 채팅창을 **Spec** 모드로 두고 아래 글을 그대로 붙여넣습니다.

```
docs/business-plan.md 와 data/questions.json 을 읽고 '사주300' 웹서비스 스펙을 만들어 줘.

[목표]
질문 하나에 300원, 결론부터 말하고 근거까지 보여주는 사주 서비스.
판정·확신도·시기는 코드가 정하고, AI는 문장만 쓴다.

[기술]
Next.js(App Router) + TypeScript + Tailwind, Supabase(회원·DB), 포트원(결제), Vercel(배포).
LLM은 서버에서만 호출하고 API 키는 .env.local에만 둔다.

[핵심 모듈]
1. lib/saju: 만세력 계산 (절입 시각 기준 월주, 입춘 기준 연주, 자시, 한국 서머타임, 시간 모름).
   테스트 필수: 기준 생년월일 20개 + 절입일·입춘일·자시·서머타임 경계 케이스.
2. lib/signals: 공통 신호 라이브러리. 신호 하나 = 순수 함수 하나.
3. lib/verdict: 질문 레시피(문서 7장)로 판정·확신도·시기 계산.
4. lib/llm: 문서 8장의 P1~P6 프롬프트를 그대로 사용. P5 코드 검수 + 캐시(명식 해시 + 질문 ID + 기준 연월).

[화면]
메인, 무료 사주 프로필 카드(공유 이미지 포함), 카테고리별 질문 목록,
질문 소개 페이지(검색용), 장바구니, 결과(판정·근거 칩·확신도·반대 신호·처방),
보관함, 궁합 초대 링크, 무료 신살 페이지, 약관·환불·개인정보 페이지.

[규칙]
- 가짜 후기·평점·누적 수를 표시하지 않는다. 'BEST' 순위는 실제 판매 데이터가 쌓일 때까지 '추천 질문'으로 표시한다.
- 결제는 장바구니 단위 건별 즉시결제. 충전식 포인트는 만들지 않는다.
- 결제 전에 "결과 생성이 시작되면 환불이 제한됩니다" 고지와 동의 체크를 받는다.
- 나는 프로그래밍 초보자다. 작업마다 무엇을 왜 했는지 쉽게 설명하고, 내가 직접 확인할 방법을 알려 줘.
- 문서와 다르게 하는 게 낫다고 판단되면, 바꾸기 전에 이유와 함께 물어봐 줘.

[진행]
문서의 '8주 실행 순서'대로 tasks.md를 만들고, requirements → design → tasks를
내가 하나씩 승인한 다음에 코드를 만들어 줘.
```

4. Kiro가 `requirements.md` → `design.md` → `tasks.md`를 차례로 보여주면 하나씩 읽고 승인합니다.
5. `tasks.md`의 1번 작업부터 **Start task**로 하나씩 진행합니다.

## 기존 사이트(saju300.vercel.app)를 이어서 고칠 경우

새로 만들지 않고 지금 저장소를 고치려면, 이 폴더의 `docs`, `.kiro`, `data`를 기존 프로젝트 폴더에 복사한 뒤 위 요청문의 첫 줄을 이렇게 바꾸세요.

```
docs/business-plan.md 를 기준으로, 지금 프로젝트를 이 설계에 맞게 고치는 스펙을 만들어 줘.
먼저 지금 코드와 문서의 차이를 표로 정리해서 보여 줘.
```
